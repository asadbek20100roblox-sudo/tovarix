# TOVARIX v0.3.0

The redesigned workspace uses a shared icon set, mobile bottom navigation, a left drawer, branch and date filters, and light and dark themes. The professional layout uses the supplied written directions. Reference image attachments were not present in the workspace.

## Build and distribution

- `npm run build:single` builds a single `dist-single/TOVARIX.html` with embedded JavaScript, CSS and SVG.
- `npm run build` builds the Web app and copies the single file to `dist/downloads/TOVARIX.html`.
- `npm run android:sync` copies the Web build into Capacitor, then `(cd android && bash gradlew assembleDebug)` builds the Android APK.
- `npm run test:single` opens a copy of the generated file through `file://` in offline Playwright Firefox. Install the test browser with `npx playwright install --with-deps firefox`. Set `TOVARIX_SCREENSHOTS` to a directory to collect the five mobile screenshots.

The HTML opens the local demo only. It requires a WebView with JavaScript enabled. If the embedding app blocks browser storage, the demo remains usable during a session and changes are lost on restart. Native hardware, cloud authentication, AI and payments require the standard configured Web or Android build. The HTML has no server credentials.

The standard Web build displays sample data when opened with `?mode=demo`. Existing local catalog data remains available through `?mode=local`. The connected workspace loads when a dedicated Supabase URL and publishable key are configured. New display names and cash totals require the v0.3.0 migrations. Apply them only to the dedicated TOVARIX project after verification.

## Dashboard data

The connected dashboard labels its sales figures as calculated from the latest 250 visible sales in the selected branch. Inventory value uses loaded stock and catalog costs. Owner cash combines open shifts with confirmed cash sales and bookkeeping returns. Expenses use recorded entries in the selected period. Financial debt balances, deliveries and net profit require additional accounting data and are omitted. Employee display names must be set by a business owner. Existing employee accounts retain their IDs and permissions.

The demo uses clearly marked sample amounts and locally recorded sales. It does not send transactions to Supabase.
