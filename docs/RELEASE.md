# Подготовка TOVARIX к выпуску

## Web и база

Создайте отдельный Supabase-проект для TOVARIX и проверьте его назначение перед применением миграций. Источник схемы находится в `supabase/migrations`. Файл `backend/schema.sql` хранит исходный черновик и не предназначен для применения вместе с миграциями. Миграции рассчитаны на новую схему. Для ранее развёрнутого черновика потребуется отдельный план переноса.

Подключите GitHub-ветку к веб-хостингу. В репозитории есть конфигурация Vercel для статического Vite-приложения. Задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` до сборки. Те же имена используются в переменных GitHub Actions. Web/PWA требует HTTPS вне localhost. Для Supabase Auth настройте домен, подтверждение почты и подходящий SMTP. Настройте URL возврата и Android deep links перед выпуском регистрации на устройствах.

Сервер проверяет права по предприятию. Сотрудники с назначенным правом действуют во всех филиалах этого предприятия. Проверяйте права отдельно для кассира, кладовщика и аналитика. PREMIUM ограничен 500 сотрудниками технически. Текущая реализация проверяет лимит при добавлении сотрудника. Политику уже активных сотрудников после понижения тарифа нужно согласовать перед запуском.

PWA кеширует ресурсы приложения и последние снимки данных по аккаунту, предприятию и филиалу. Для работы без сети нужна ранее открытая сессия. Касса хранит один неподтверждённый запрос на сочетание аккаунта и филиала и повторяет его с тем же UUID. Запасы и цены проверяет PostgreSQL в момент проведения. Подтверждённый чек появляется после ответа базы. Офлайн-изменения каталога, склада, смен и возвратов пока не поддерживаются. Снимки находятся в хранилище браузера, поэтому кассу следует использовать через индивидуальные профили устройств.

## Резервные копии

Согласуйте расписание и защищённое хранилище. Используйте резервные копии выделенного Supabase-проекта и проверяйте восстановление на отдельной базе. Для собственного PostgreSQL команда `scripts/backup.sh /secure/path/tovarix.dump` создаёт закрытый логический архив через `pg_dump` и проверяет его оглавление. Задайте `TOVARIX_BACKUP_DB` через libpq service либо строку подключения, а секреты храните вне репозитория. Служебные роли, права и внешнее хранилище этим архивом не восстанавливаются.

## AI

Задайте серверные `GEMINI_API_KEY`, `GEMINI_MODEL`, `TOVARIX_ALLOWED_ORIGINS`. Через приватные таблицы `trial_features` и `entitlements` предоставьте явно согласованное право `ai`. По умолчанию оно выключено. На предприятие выделено 20 запросов в день по времени Ташкента. Провайдер получает агрегаты продаж и ограниченный снимок остатков. Инструменты изменения данных ему не предоставляются. Endpoint принимает необязательное изображение в base64, а экран пока отправляет текстовые вопросы.

## Платежи и оборудование

Каталог сохраняет согласованные месячные и годовые цены. FREE применяется для неоплаченной или истёкшей подписки. Пробный период длится один календарный месяц, а его возможности включаются через приватную таблицу. Промокоды ограничены двумя выпусками в месяц по Ташкенту, тремя применениями кода и одним применением на аккаунт. Выдача доступна сервисной роли. Применение фиксирует право на скидку. Сервисный RPC `open_promo_order` резервирует это право и рассчитывает итоговую сумму. Скидка 100% оформляется как промопредоставление доступа с записью аудита без платёжного события.

Для платёжного подключения нужен PSP, его адаптер Checkout и доверенный relay. Сервер адаптера предварительно проверяет владельца и создаёт заказ через сервисный RPC `open_billing_order`. Relay проверяет исходную подпись и статус PSP, затем пересылает подтверждённое событие `{type:"payment.captured",provider,id,order,amount,currency:"UZS"}`. Заголовок `x-tovarix-timestamp` содержит Unix-секунды. `x-tovarix-signature` содержит hex HMAC-SHA256 от `timestamp + "." + rawBody`. Параметры сервера `TOVARIX_PAYMENT_RELAY_SECRET` и `TOVARIX_PAYMENT_PROVIDER` определяют ключ и провайдера. Webhook сверяет сумму, заказ и валюту и обрабатывает повтор атомарно. Развёртывайте функцию вместе с реальным адаптером. Публичный платёжный checkout пока отсутствует.

На кассе карта означает внешнее получение через терминал. Полный возврат восстанавливает склад и записывается в учёте. Возврат денег выполняется на стороне кассы или терминала. Внутренний чек печатается через системный диалог. Для официального чека нужен согласованный фискальный провайдер Узбекистана. Прямое подключение принтера, весов и денежного ящика подготовлено через интерфейсы. Проверка HID и камеры на реальном Android, фискальная интеграция, подписанная релизная сборка и публикация в магазине остаются этапами выпуска.

## Текущие ограничения

- Операции по партиям и серийным номерам, взвешиваемые продажи, частичные возвраты и приглашения сотрудников по почте требуют реализации.
- Закупка поддерживает приём одной товарной позиции на документ и историю приёмки. Продажа не пересчитывает себестоимость из закупок автоматически.
- Финансы показывают выручку, валовую прибыль, маржу и способы оплаты по данным продаж. Бухгалтерские расходы и сверка денежных остатков смены требуют реализации.
- Экран поддержки показывает маршрут обращения к владельцу или PixelForge UZ. Система заявок отсутствует.
- PWA и Android используют общую кодовую базу. iOS-проект и подписанные сборки ещё не создавались.
