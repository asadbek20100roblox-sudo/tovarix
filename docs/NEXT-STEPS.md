# TOVARIX v0.4.0 · точка продолжения

Ветка `codex/tovarix-commerce`, PR №1. Публичный алиас `tovarix-uz.vercel.app` продолжает обслуживать v0.3.0. v0.4.0 проверяется в защищённых Vercel Preview. Supabase `jkjexgcssglzweayztel` подготовлен к синтетическим проверкам. Порядок и ограничения описаны в [отчёте](V0.4-READINESS.md).

## Что делать следующим

1. Получить два исходных файла логотипа в рабочую папку. Сохранить оригиналы и изготовить перечисленные размеры из тех же изображений. Проверить safe zone Android и PWA.
2. Получить утверждённые условия, заключение по размещению персональных данных и выделенные тестовые почтовые ящики. В Supabase проверить SMTP, ограничения Auth, Site URL и разрешённые redirect URLs. Выполнить реальный цикл подтверждения email и восстановления пароля.
3. Назначить первого platform admin через доверенную серверную операцию в `commerce_private.platform_admins`. У пользователя должен быть подтверждённый аккаунт и настроенный TOTP. Проверить живой AAL2 challenge. Существующее SQL-покрытие подтверждает серверный запрет на данные при AAL1.
4. После разрешения на пробный вызов Gemini задать точный `TOVARIX_ALLOWED_ORIGINS`, проверить доступность секрета на сервере, одобрить тестового арендатора и установить минимальный дневной лимит. Проверить ответ на искусственных данных. Текущая функция развёрнута, глобальный выключатель установлен в false.
5. Продолжить с индивидуальным RBAC, приглашениями, защитой просмотра себестоимости, полным учётом долгов и складскими сущностями. Затем закончить полный список тарифных возможностей, CONTROL, подтверждаемые AI-предложения и интеграции Click/Payme.

## Миграции на удалённом проекте

Исходная публичная схема была пуста. DDL развёрнут в порядке локальных файлов через инструмент Supabase. Удалённые номера версий созданы сервером. Имена сохраняют локальные номера и имеют префикс `tovarix_`. Перед использованием CLI `db push` сопоставить миграции по именам с удалённой историей. Повторное применение исходного набора создаст конфликт.

## Воспроизводимые проверки

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm audit
npm run build
npm run build:control
npx playwright install firefox
npm run test:single
```

`npm run test:postgres` использует отдельный PostgreSQL 17 через `TOVARIX_TEST_POSTGRES`. `npm run test:browser` использует локальное приложение, GoTrue и PostgREST через `TOVARIX_TEST_WEB`. Для браузерного сценария нужна тестовая конфигурация с автоподтверждением email.
